Most network tools throttle your whole machine.

Throttlr does it per-process.

Lagging your whole computer to test what one app does at 300ms ping is overkill. You want to throttle just that one app — while your stream stays smooth, your downloads finish, and every other process keeps running like nothing happened.

That's the gap Throttlr fills. By hooking into the WinDivert kernel driver, it matches packets to a single process ID and intercepts only those — at the network layer, before they ever hit the wire.

A second kernel-level handle listens for connection events in real time, so process resolution is instant and bulletproof — no polling delay, no timing windows, no missed flows. Whatever app you target, every packet it touches gets caught.

And because it all runs at the kernel level, the targeted app sees real network conditions. There's nothing to detect, nothing to bypass. From the app's perspective, your connection just got worse.

A second WinDivert handle runs in SNIFF mode on the FLOW layer, listening for connection-establishment events. Frequently asked.

Is this safe? Will it brick my system or get me banned?

Throttlr operates at the kernel level via WinDivert, the same widely-trusted driver used by tools like clumsy, NetBalancer, and Glasswire. It doesn't modify game files, inject code, or alter system memory — it only intercepts your own network traffic. Anti-cheat systems generally do not flag it because there's nothing to flag: from the game's perspective, your network connection just got worse.

That said: use your judgment. Some competitive games may have specific clauses against using anything that affects gameplay. Throttlr is designed for testing, learning, and content creation — not for cheating in ranked.

Why does it need administrator privileges?

WinDivert installs a kernel-mode driver to intercept packets before they hit your network adapter. Loading kernel drivers requires admin rights — there's no way around it. The installer handles elevation at install time, and the launcher requests it on launch automatically. Just click "Yes" on the UAC prompt.

Does it phone home? Any telemetry?

Zero. No analytics, no crash uploads, no anything sent to anyone. The only intentional outbound call Throttlr makes is the GitHub Releases check at launch (for auto-update), and that's a single anonymous GET to GitHub's public API. Even that can be turned off in Settings → Behavior → Auto-update.

The source isn't fully public anymore (Throttlr went closed-source at v3.0.8 to make piracy resilience meaningful), but the binary's network behaviour is easy to verify with any packet sniffer — run Wireshark on your machine, launch Throttlr, watch what it sends. It's exactly the GitHub check and nothing else.

Can it throttle browser tabs individually?

No — Throttlr matches at the process level, and modern browsers run all tabs inside the same parent process (or a small set of helper processes). It can throttle Chrome as a whole, but not youtube.com while leaving github.com alone. For tab-level throttling you'd want a browser extension.

How is it different from clumsy?

Clumsy works at the system level — its filters apply to all traffic matching a filter expression, not specifically to one app. It's a great tool, but it requires you to write tcpdump-style filters and can't say "throttle Discord but leave Chrome alone" without you knowing the IPs/ports involved.

Throttlr targets a specific running process by name (or PID), and the kernel-level FLOW listener tracks every connection that process makes — so all traffic for that app is captured automatically, regardless of which IP/port. Plus the UI is, well, an actual UI.

Mac or Linux support?

Not currently. Throttlr depends on WinDivert which is Windows-only. A Linux equivalent would have to be rebuilt around iptables + nfqueue or eBPF — different architecture entirely. macOS is even harder since modern macOS heavily restricts kernel extensions. Windows-only for the foreseeable future.

Will Windows SmartScreen warn me when I run it?

Yes — because the .exe isn't signed with a paid code-signing certificate. This is normal for indie Windows apps and is just a "we don't recognize this publisher" warning, not a threat. Click "More info" → "Run anyway" and it'll launch fine.

Can I throttle multiple apps at once?

Yes — there's a Multi-Target mode in the Application panel. Click the ⊕ MULTI-TARGET button, then add multiple .exe files to the target list. The same function settings apply to all of them simultaneously. Useful for game launchers that spawn helper processes (Riot Client, Battle.net, etc).

What if I find a bug?

Open an issue on GitHub: github.com/BillysMatrix18/throttlr-releases/issues. Throttlr also writes crash logs to ~/.throttlr/crashes/ — including those in your bug report makes diagnosis way faster.
